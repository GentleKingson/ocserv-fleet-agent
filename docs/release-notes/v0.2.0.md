# ocfleet v0.2.0 Release Notes

## Summary

`v0.2.0` is a conservative read-only observability release candidate for
controlled evaluation. It expands controller-local scheduling, health, alert,
retention, audit export, API/dashboard, trust-policy review, and local snapshot
collection without adding a generic execution or live ocserv write path.

This release is not production-complete. Review the current boundaries in
[`SECURITY.md`](../../SECURITY.md) and the implementation status in
[`docs/status.md`](../status.md) before deployment.

## Added

- Controller-local scheduler jobs, runs, bounded observations, derived health,
  alert event evaluation, observability retention, and bounded audit export.
- An experimental `GET`-only `ocfleet-api` contract with an OpenAPI document
  and a static read-only dashboard.
- `ocfleet-ocserv-collector`, an operator-run local normalizer that emits only
  the fixed low-sensitive `ocfleet.ocserv.snapshot.v2` schema.
- TOML/YAML trust-policy validation and deterministic JSON or bounded Markdown
  diff output. Trust policy remains review-only and has no apply command.
- Actor/RBAC and backend trait foundations. SQLite remains the implemented
  default backend; the optional Postgres feature is non-connecting scaffolding.
- Default-off controlled-write DTO/config scaffolding. Even feature-enabled
  builds provide validation/dry-run design only, not live dispatch.

## Security Boundary

- Agent RPC methods remain fixed and typed. There is no shell, command, script,
  raw execution, raw file, raw log, raw config, or raw certificate interface.
- There is no `systemctl`, `occtl`, or `journalctl` passthrough.
- There is no live reload, restart, config apply/rollback, or session disconnect.
- The API and dashboard expose no write route or control action.
- The collector is local and operator-controlled; controller RPC, scheduler,
  API, and dashboard code cannot invoke it or select its local paths.
- Trust remains explicit. There is no TOFU, automatic registration, automatic
  path authorization, mesh enumeration, or multi-hop relay probe.

## Release Artifacts

The release workflow builds these four binaries for both `linux-x86_64` and
`linux-aarch64`:

- `ocfleet`
- `ocfleet-agent`
- `ocfleet-api`
- `ocfleet-ocserv-collector`

`SHA256SUMS` covers all eight binaries in the draft GitHub Release. The workflow
accepts only a bounded SemVer tag, requires the selected workflow ref and input
version to be the same existing tag, and refuses a binary whose compiled package
version differs from that tag.

## Install

Follow [`docs/install.md`](../install.md). The local build short form is:

```bash
./scripts/build-release.sh v0.2.0
./scripts/verify-checksums.sh dist/v0.2.0/SHA256SUMS
OS="$(uname -s | tr '[:upper:]' '[:lower:]')"
ARCH="$(uname -m)"
case "$ARCH" in arm64) ARCH="aarch64";; amd64) ARCH="x86_64";; esac
for binary in ocfleet ocfleet-agent ocfleet-api ocfleet-ocserv-collector; do
  sudo install -m 0755 \
    "dist/v0.2.0/$binary-v0.2.0-$OS-$ARCH" \
    "/usr/local/bin/$binary"
done
```

Installing `ocfleet-api` or the collector binary does not enable a service.
Keep the API loopback-only unless a private bearer-token file is configured,
and follow [`docs/collector.md`](../collector.md) before enabling the collector
timer.

## Upgrade

Back up the controller SQLite database and all controller/agent SecretKeys
before replacing binaries. The SQLite schema is versioned; an older non-empty
database is privately backed up before migration. After installation, run:

```bash
ocfleet --database /var/lib/ocfleet-controller/controller.sqlite \
  --secret-key /var/lib/ocfleet-controller/controller.secret doctor --json
```

The `registry.endpoint_trust.coverage` doctor check must be `ok` before any
controller or scheduler RPC smoke. This release treats a missing trust row as
not authorized and rechecks source and path-target trust immediately before
dispatch. If the coverage check fails, keep RPC and scheduler execution
stopped, retain the backup, and either restore a known-good database or
explicitly re-register each affected node with its operator-verified
EndpointID. The controller never recreates trust from a node row automatically.

Retain the pre-upgrade database until `doctor`, controller-local queries, and an
expected low-sensitive read-only RPC smoke all pass.

## Known Limitations

- The release remains an evaluation-stage read-only control plane, not a
  production support commitment.
- SQLite is the only runtime backend. Postgres code does not connect, migrate,
  import, or write.
- API bearer tokens map only to the viewer role, and the API remains `GET`-only.
- The collector normalizes a local operator-managed snapshot; it does not call
  service managers, admin tools, logs, or controller-selected providers.
- Controlled writes remain default-off design and validation scaffolding. No
  live operation code path exists.
