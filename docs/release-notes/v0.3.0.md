# ocfleet v0.3.0 Release Notes

## Summary

`v0.3.0` is the production-foundation release for the read-only ocserv fleet
control plane. It completes the A1-A8 reliability, security, observability,
backup/restore, and release-engineering gates while preserving explicit trust,
fixed typed RPCs, GET-only web surfaces, and default-off controlled writes.

## Production Foundation

- Every controller mutation family uses actor-bound atomic state-plus-audit
  writers; direct mutation bypasses are guarded in CI.
- Closed versioned SQLite payloads and migrations fail closed on unknown,
  contaminated, oversized, secret-like, or address-bearing data.
- Scheduler leases, fences, recovery, retry/backoff, misfire, jitter, timeout,
  maintenance, budget, and graceful shutdown semantics are durable.
- Health evaluation runs independently of dashboard reads and persists bounded
  input watermarks, policy/computation versions, snapshots, and failures.
- Alert delivery uses a fenced durable queue with bounded retry, dead-letter,
  rate limits, HMAC, HTTPS/SSRF enforcement, no redirects, and no command hooks.
- Managed backup and restore provide checksums, optional signatures, identity
  and schema checks, pre-backup, WAL/SHM handling, atomic replacement, rollback,
  and an automated drill.
- Agent and controller Prometheus exporters are loopback-default, protected on
  non-loopback listeners, and limited to fixed low-cardinality labels.

## Release Evidence

- Default/all-feature format, Clippy, and test gates.
- Protocol/frame/config libFuzzer smoke and deterministic schema 1-current
  migration/contamination corpus.
- Chromium desktop/narrow dashboard E2E that rejects non-GET browser traffic.
- Debian Trixie and Ubuntu 24.04 install smoke on Linux x86_64 and aarch64.
- CycloneDX 1.5 SBOMs, keyless Sigstore bundles, GitHub build provenance, and
  independent verification before draft release creation.
- SHA-pinned GitHub Actions, least-privilege job permissions, cargo-deny,
  cargo-audit, and CodeQL.

## Upgrade And Rollback

Direct upgrades from `v0.1.x` and `v0.2.x` are supported through the complete
migration corpus. Follow `docs/release-policy.md` and
`docs/release-rollback-runbook.md`: stop controller processes, verify a managed
backup, verify release supply-chain evidence, upgrade all four binaries, run
`doctor --json` and `trust diff`, then restart components in order. An older
binary must never open the migrated database; rollback restores the verified
pre-upgrade database before reinstalling older binaries.

## Security Boundary

There is still no shell, generic command, raw file/log/config interface,
automatic enrollment, TOFU, mesh enumeration, multi-hop relay, or web/API
mutation route. Controlled-write DTOs remain feature-gated scaffolding with no
live dispatch in either the default or all-feature build.

## Known Limits

- SQLite is the only production backend; Postgres remains non-connecting
  scaffolding.
- The API uses bearer authentication and relies on an external TLS boundary for
  non-loopback deployment.
- Local ocserv collection remains an operator-managed reduced snapshot
  normalizer rather than live service-manager or admin-tool discovery.
- Stage B read-only product capabilities and later scale/HA milestones remain
  governed by `docs/next-roadmap.md` and are not implied by this release.
