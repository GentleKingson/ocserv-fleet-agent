# Release Supply-Chain Verification

The tag-bound draft release workflow produces Linux x86_64 and aarch64
binaries, CycloneDX 1.5 SBOMs, SHA-256 manifests, Sigstore bundles, and GitHub
build-provenance attestations. Draft creation stops unless every downloaded
artifact passes independent checksum, SBOM, signature, and provenance checks.

## Trust Model

- The workflow accepts only an exact SemVer tag matching its requested version.
- Remote actions are immutable commit-SHA pinned and checkout credentials are
  not persisted.
- Build jobs have only `contents: read`, `id-token: write`, and
  `attestations: write`. The final job alone receives `contents: write` to create
  a draft release.
- Sigstore signing is keyless. Verification restricts certificate identity to
  this repository's `release.yml` on a SemVer tag and restricts the issuer to
  GitHub Actions. There is no long-lived signing secret.
- Provenance is generated by GitHub's artifact-attestation service and verified
  against `GentleKingson/ocserv-fleet-agent` before release creation.
- SBOM generation uses pinned `cargo-cyclonedx` and the locked Rust dependency
  graph. Five component SBOMs are emitted for each architecture.

## Release Files

Each architecture includes four executables, five `*.cdx.json` SBOMs, and a
`*.sigstore.json` bundle beside every executable and SBOM. The assembled release
also includes `SHA256SUMS` and its Sigstore bundle. `SHA256SUMS` covers every
binary, SBOM, and per-file signing bundle in deterministic filename order.

## Independent Verification

Install `cosign`, `jq`, and GitHub CLI, download all release assets into one
directory, then run:

```bash
scripts/verify-checksums.sh ./release-files/SHA256SUMS
scripts/verify-release-supply-chain.sh ./release-files v0.2.0
for artifact in ./release-files/ocfleet-*; do
  case "$artifact" in *.sigstore.json) continue ;; esac
  gh attestation verify "$artifact" \
    --repo GentleKingson/ocserv-fleet-agent
done
```

Finally verify the combined checksum signature with the same certificate
identity and issuer constraints documented in
`scripts/verify-release-supply-chain.sh`. A missing file, malformed SBOM,
checksum mismatch, wrong workflow identity, wrong issuer, invalid signature, or
missing repository attestation is a hard failure. Do not install the candidate.

Draft releases are deliberately not promoted automatically. Publication still
requires review of release notes, the complete verification output, install
smoke results, and the upgrade/rollback matrix.
